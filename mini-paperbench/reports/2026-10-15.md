JudgeEval Code-Dev 40개, 프롬프트 약 33k 토큰, GPU 1장.

## 4. 문제와 해결

| 문제 | 원인 | 해결 |

## 5. 결론

1. **judge 모델의 크기와 품질이 결과를 좌우한다.** 같은 파이프라인, 같은 프롬프트로도 7B 모델은 Gemini보다 크게 뒤진다.
2. **F1 하나로는 판단할 수 없다.** 정답이 1점에 쏠려 있으면, 아무것도 안 보는 judge의 F1도 높다. macro-F1, 0점 재현율, "전부 1점" 기준선을 같이 봐야 한다.
3. **합성 논문은 judge 검증에 유용하다.** 비용이 작고, 0점이 충분하고, 어떤 종류의 오류를 놓치는지 볼 수 있다.
4. **분산 처리는 잘 동작한다.** 로컬 judge 실험 37개 run, 작업 932개가 **모두 끝났다.** 중간에 예외가 4번 났지만 다른 워커가 이어받았고, 포기한 작업 0개, 두 번 완료된 작업 0개다.

## 7. 재현 방법

```bash
cd mini-paperbench
python scripts/import_synthetic.py datasets/synthetic_*.zip

# 로컬 GPU judge 켜기 (비어 있는 GPU 번호를 먼저 확인)
GPU=2 MAX_LEN=49152 EXTRA_ARGS='--rope-scaling {"rope_type":"yarn","factor":2.0,"original_max_position_embeddings":32768}' \
  scripts/vllm_server.sh start

export LLM_BASE_URL=http://127.0.0.1:8011/v1 LLM_API_KEY=local LLM_MODEL=Qwen/Qwen2.5-7B-Instruct \
       RATE_LIMIT_RPM=100000 RATE_LIMIT_TPM=1000000000 CLAIM_IDLE_SEC=300
scripts/redis.sh start
WORKERS=6 scripts/run_synthetic.sh q7b                       # 합성 논문 6편
scripts/run_local.sh je_q7b 77 4                              # JudgeEval
python -m judge.judgeeval --name Qwen_Qwen2.5-7B-Instruct \
  --pair je_q7b=data/judge_eval/semantic-self-consistency/0/expected_result.json

scripts/redis.sh stop
scripts/vllm_server.sh stop                                    # 공용 서버: 반드시 끈다
```

참고: 합성 논문 6편은 컨텍스트 32k(YaRN 없이)로 돌렸고, JudgeEval·에이전트·속도 실험은 YaRN 48k로 돌렸다.

## 9. 추가 (10월 16일): Gemini로 합성 논문 6편 전체 채점

### 9-1. 하루 한도의 실제 초기화 시각
- Google 공식 문서: "Requests per day (RPD) quotas reset at **midnight Pacific time**."
  - 10월(서머타임)에는 **한국 시간 16:00**, 11월부터는 **17:00**이다.
- 429 오류 안의 `retryDelay`는 한국 시간 09:00(UTC 자정)을 가리켰다. 이 값을 믿고 10월 15일 10:10에 예약 실행했다가 실패했다(162개 중 4개만 채점). 결과는 버렸다.
- 한도는 **API 키가 아니라 프로젝트 단위**다. 새 키를 만들어도 늘지 않는다.
- 고친 것: 429 메시지에 `PerDay`가 있으면 재시도하지 않는다. 워커는 run을 "중단"으로 표시하고 멈추고, `run_synthetic.sh`도 남은 run을 실행하지 않는다.
